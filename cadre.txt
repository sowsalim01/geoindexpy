# PROMPT MAÎTRE — CONCEPTION ET DÉVELOPPEMENT DE GEOINDEXPY

## 1. IDENTITÉ DU PROJET

Je souhaite développer une bibliothèque Python open source nommée **GeoIndexPy**.

GeoIndexPy est le pendant Python du projet R **GeoIndexR**, mais il ne doit pas être une simple traduction ligne par ligne.

Le projet doit être conçu comme une **bibliothèque Python scientifique, moderne, robuste, extensible, performante et documentée**, destinée principalement à la télédétection, à la géomatique, à l'analyse d'images multispectrales et à la data science géospatiale.

### Nom

```text
GeoIndexPy
```

### Domaine

* Télédétection
* Géomatique
* Earth Observation
* Remote Sensing
* Analyse d'images multispectrales
* Analyse d'images hyperspectrales
* Données raster
* Data Science géospatiale
* Calcul d'indices spectraux
* Machine Learning géospatial à terme

---

# 2. OBJECTIF GÉNÉRAL

GeoIndexPy doit permettre de calculer facilement, rapidement et de manière reproductible des **indices spectraux et géospatiaux** à partir de données raster.

L'objectif est de permettre des opérations simples comme :

```python
import geoindexpy

ndvi = geoindexpy.ndvi(
    nir=nir,
    red=red
)
```

ou :

```python
result = geoindexpy.calculate_index(
    image,
    index="NDVI"
)
```

ou encore :

```python
results = geoindexpy.calculate_indices(
    image,
    indices=["NDVI", "NDWI", "NDBI"]
)
```

La bibliothèque doit également permettre :

```python
geoindexpy.list_indices()
```

afin que l'utilisateur puisse découvrir les indices disponibles.

17. Séparation entre calcul scientifique, données raster et visualisation.
18. Préparation à une publication sur PyPI.

# 4. POSITIONNEMENT PAR RAPPORT À GEOINDEXR

GeoIndexPy doit reprendre les concepts fondamentaux de GeoIndexR :

```text
Image raster
      ↓
Identification des bandes
      ↓
Validation
      ↓
Sélection de l'indice
      ↓
Calcul
      ↓
Raster résultat
```

GeoIndexR utilise notamment `terra`, tandis que GeoIndexPy doit privilégier l'écosystème Python adapté.

L'architecture Python doit notamment étudier :

```text
NumPy
Rasterio
xarray
rioxarray
GeoPandas
Shapely
Dask
```

Cependant, **ne pas rendre toutes ces bibliothèques obligatoires**.

Il faut distinguer :

### Core dependencies

Bibliothèques indispensables au moteur.

### Optional dependencies

Bibliothèques activées uniquement pour certaines fonctionnalités :

```text
visualisation
cloud processing
xarray
dask
geopandas
```

# 14. FORMULES

Chaque formule doit être implémentée explicitement et documentée.

## NDVI

```text
NDVI = (NIR - RED) / (NIR + RED)
```

## SAVI

```text
SAVI = ((NIR - RED) / (NIR + RED + L)) × (1 + L)
```

avec :

```text
L = 0.5
```

par défaut.

## EVI

```text
EVI =
G × (NIR - RED)
-------------------------
NIR + C1×RED - C2×BLUE + L
```

Paramètres par défaut :

```text
G  = 2.5
C1 = 6
C2 = 7.5
L  = 1
```

## GNDVI

```text
GNDVI = (NIR - GREEN) / (NIR + GREEN)
```

## NDWI

```text
NDWI = (GREEN - NIR) / (GREEN + NIR)
```

## MNDWI

```text
MNDWI = (GREEN - SWIR) / (GREEN + SWIR)
```

## NDBI

```text
NDBI = (SWIR - NIR) / (SWIR + NIR)
```

## NDMI

```text
NDMI = (NIR - SWIR) / (NIR + SWIR)
```

Pour chaque formule, identifier précisément la variante utilisée.

# 24. GESTION DES NaN / Inf / NoData

```text

```

Prévoir éventuellement :



# 25. SCALING / REFLECTANCE

Le package doit explicitement documenter le problème des valeurs :

```text
0–10000
```

versus :

```text
0–1
```

Ne jamais appliquer automatiquement :

```python
reflectance = values / 10000
```

sans indication explicite.

Prévoir éventuellement :

```python
scale_factor=0.0001
```

ou une fonction dédiée :

```python
apply_scale(...)
```

Le comportement doit être totalement transparent.

Les indices normalisés sont généralement invariants à un facteur multiplicatif commun, tandis que les indices comportant des constantes additives nécessitent davantage d'attention.

# 83. OBJECTIF FINAL DU PROJET

L'objectif n'est pas simplement de créer quelques fonctions Python telles que :

```python
ndvi()
ndwi()
ndbi()
```

L'objectif est de construire un **véritable moteur scientifique d'indices spectraux**.

Le concept central doit être :

```text
                 GeoIndexPy
                     │
                     ▼
              Index Registry
                     │
                     ▼
               Index Engine
                     │
        ┌────────────┼────────────┐
        ▼            ▼            ▼
      Bands        Formula      Metadata
        │            │            │
        └────────────┼────────────┘
                     ▼
              Validation Engine
                     │
                     ▼
               Raster Engine
                     │
                     ▼
             NumPy / Rasterio
                / xarray
                     │
                     ▼
                Resultat
```

Le projet doit donc être pensé comme une **infrastructure logicielle scientifique**, et non comme une collection de fonctions indépendantes.
